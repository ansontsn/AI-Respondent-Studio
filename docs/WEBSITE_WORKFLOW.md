## 生成人物時就有姓名

到「虛擬人物管理 → 建立人物」，設定模型、人數、Seed 與背景，按「生成並儲存人物」。**生成當下即有中文姓名**，不是提交設計時才補名字。Mock 用人物 ID 推導可重現的虛構中文姓名，不增加 API 請求；真實模型提示要求姓名，若只提供編號則本機補足，真實模型姓名品質尚未實測。

同批避免重複名字，同 ID 重跑保留使用者修改過的姓名。人物 ID 仍是主鍵；核心背景和人格不因方案分配而改變，舊回答快照不改寫。舊匯入人物可自行編輯姓名，不任意重寫歷史資料。

## 三種流程

| 方案 | 真正操作內容 |
|---|---|
| BASIC | 框色、預覽；不輸入文字或加入背景貼飾 |
| CUSTOM | 框色、文字、字體、文字位置與文字色、預覽 |
| PREMIUM | 上述文字操作，再選背景、加入貼飾、核對配置與預覽 |

皆可預覽或可選設計提交。Playwright 操作不逐步呼叫 AI；這是固定／規則流程，不是任意網站自由探索。目前使用網站示範小卡，未支援所有背景／貼飾、所有自由拖曳或自行上傳照片。

BASIC 有網站原有的降級確認；只在選方案階段接受經核對的特定訊息。依 [Playwright 官方對話說明](https://playwright.dev/python/docs/dialogs) 處理，不直接改 React 狀態或繞過權限。

## 讓三種流程都有人執行

1. 生成人物至少 3 人，到「網站體驗模擬」選流程，先保留僅預覽。
2. 按「建立獨立的網站操作測試問卷」，建立三方案 8 題測試問卷，去問卷管理查看並確認。舊 CUSTOM 測試問卷與正式問卷不覆蓋。
3. 回到網站體驗，選模型、問卷、人物，勾「分配人物至三種方案」。
4. 填 BASIC、CUSTOM、PREMIUM 人數，合計等於選取人物數；三種都要有人跑時各至少 1 人。例如 3 人各 1 或 30 人各 10。
5. 查看姓名、人物 ID 與方案分配，設定 Seed／預算，建立任務並開始。
6. 在歷史與回答檢查看姓名、方案、截圖、理由及修正紀錄，既有控制台支援暫停、停止、續跑和重排失敗回答。

分配按 Seed 重現，只是自訂情境，不是人口比例。同一任務每位人物分配一種方案；同一人物比較三方案可建立三個單方案任務並沿用人物。同人物同設計可使用完成紀錄，品質重生成不重新提交。新欄位有預設值，舊 CUSTOM 任務及提交防護維持相容，原 SQLite 資料保留。

## 提交姓名與雲端保存

預設「提交時使用人物生成時的姓名」；網站姓名欄填各人物姓名，信箱另設。`ai-test@example.invalid` 是保留的測試格式，不會收到信件；未勾選才使用固定測試姓名。

提交前核對自有／授權用途，確保 AI 設計與真人研究紀錄分開；選提交、確認授權並儲存。相同人物同設計跨任務仍阻擋重送，結果不明不自動重試。

**網站版本已改變**：2026-10-13 的實測提交走瀏覽器本機備援；2026-10-14 公開程式與被攔截寫入已讀到 Supabase 設定 `https://xxyezsyemwokvjnwwfke.supabase.co`。這不證明雲端寫入授權或接收已成功。

「偵測網站設計接收網址（唯讀）」只讀公開 HTML 和同來源程式，帶入 URL，不輸出／保存 Key，不提交。進階欄位核對 `/rest/v1/design_submissions` 接收網址後儲存；不是 AI Base URL。預覽仍禁寫入；提交只放行一次相符姓名／信箱／方案／文字的設計新增及同後端的預覽圖上傳。

| 結果 | 證據 |

| 成品預覽完成 | 完成設計與截圖，未送出 |
| 已存本機 | 網站本機已有相符紀錄並備份，未證明研究端收到 |
